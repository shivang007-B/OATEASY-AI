# FreshFlow ML — Datasets, Models and Engine

Synthetic-data implementation of the FreshFlow design: three datasets, two trained models, and a rule-based recommendation engine.

> **All data here is synthetic.** It is generated by explicit rules in notebook 01, because no real restaurant POS, inventory or waste logs were provided. The models show that the pipeline works end to end. Their metrics describe the synthetic process, not a real restaurant. Before trusting any accuracy claim, retrain on real logs and evaluate on a held-out period.

## Run order

Run the notebooks in order: 01 → 02 → 03 → 04. Each notebook reads from `../data`, `../models` and `../outputs` relative to its own folder, so run them from the `notebooks/` directory or with it as the working directory.

## The three datasets

| Dataset | Grain | Rows | Feeds |
|---|---|---|---|
| 1 — Sales & demand | date × restaurant × dish | 17,520 | Model 1 |
| 2 — Inventory & waste | date × restaurant × ingredient | 24,854 | Model 2 |
| 3 — Recipe & purchasing | date × restaurant × ingredient (requirements), plus purchase orders | see file | Engine 3 |

Shared keys: `restaurant_id`, `dish_id`, `ingredient_id`, `date`. These let the outputs join reliably.

Dataset 2 satisfies a stock balance on every row:
`opening + received − expired − spoilage − usage − over-prep = closing`. Notebook 01 asserts this.

## Model results (held-out test period, 1 Jul 2025 onwards)

**Model 1 — dish demand** (WAPE = total absolute error ÷ total actual orders; lower is better)

| Method | MAE | RMSE | WAPE |
|---|---|---|---|
| Seasonal naive (same weekday last week) | 7.10 | 9.46 | 25.4% |
| 28-day moving average | 5.69 | 7.65 | 20.4% |
| **Gradient boosting, Poisson loss (Model 1)** | **4.90** | **6.52** | **17.6%** |

The 80% prediction interval covers 74% of actual outcomes, slightly below the nominal 80%. Treat the intervals as approximate.

**Model 2 — ingredient waste risk** (any discard on the next 3 days)

| Method | ROC-AUC | PR-AUC |
|---|---|---|
| Rule: days to expiry | 0.878 | 0.797 |
| Rule: stock cover days | 0.243 | 0.263 |
| **Gradient boosting classifier (Model 2)** | **0.913** | **0.851** |

Dry goods have shelf lives of months and essentially never generate waste in this data, so the classifier mostly separates perishables. The rule baselines remain useful checks.

**Engine 3 — recipe-based requirement accuracy** (last 90 days, median across ingredients)

- Ignoring prep yield loss: 5.8% error
- Including prep yield loss (as the engine does): 0.1% error

## How the engine works

1. Prep per dish = forecast median × (1 + 10% safety buffer).
2. Gross requirement = forecast orders × recipe quantity ÷ (1 − prep yield loss).
3. Net shortfall = requirement + buffer − usable stock − incoming deliveries, rounded up to the supplier minimum order quantity.
4. Actions are ranked by avoidable cost × feasibility.

The headline "potential waste avoided" in `report_summary.json` is an estimate from these ranked actions. It is labelled "Estimated, not verified" in the output and should not be presented as a measured saving.

## Limits and next steps

- Replace the synthetic data with real POS, stock-batch and waste logs. Keep the same column names so the notebooks run unchanged.
- The forecast uses a climatological temperature placeholder and assumes no rain and no promotion for the next day. Use a real weather forecast and the planned promotion calendar in production.
- Usable-stock logic is conservative: any stock with less than one day to expiry is treated as unusable.
- Retrain Model 1 and Model 2 periodically as new outcomes arrive, and track model versions alongside each prediction.
